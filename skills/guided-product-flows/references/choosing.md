# Choosing each tool's path

Every tool needs *a* way in that isn't a blank page. It doesn't have to be a
wizard. Pick by what the tool is for.

## Guide (a wizard of 3–5 steps)

**When:** the tool's value is a handful of decisions the user has to make:
positioning, priorities, a plan, a model, a map.

**Test:** can you write each step as one question only the user can answer?
"Who will you win first?" yes. "Fill in the 9 boxes" no: that is a form, so
find the decisions under it.

**Shape:**
- 3–5 steps; past 6, split the tool or merge steps.
- Each step offers options gathered from other tools, plus "Or write your own".
- The last step either writes the result or offers an AI draft around the decisions (with a no-AI save).

## Checklist ("before you send it")

**When:** the tool is assembled from others: a summary, a 1-pager, a data
room, an export, a report.

**Why not a wizard:** there's nothing to decide here. Its quality is the
quality of the tools it reads from, so the useful thing is to say what's
missing and send the user to fix it there.

**Shape:**
- 6–10 checks phrased as what the reader looks for ("Has evidence from real customers").
- Missing items first, each with a one-line reason and a button that opens the tool that fills it.
- A progress line ("3 of 8 ready").
- Anything the tool *says* (an email teaser, a summary) claims only what the checks show exists.

## Setup brief (before a session)

**When:** the tool is a conversation, a practice run or a live session: a
pitch rehearsal, an interview simulator, a chat with a persona.

**Shape:**
- 2–3 questions that make the session about the user's real situation: who is across the table, what you're asking for, what worries you most.
- Pre-fill from other tools (the ask from the deck).
- Suggest the worry from gaps in the user's own work ("How do you know landlords will pay £10?" when that assumption is untested).
- The brief is saved with the session and sent to the AI on every turn, not just the first.
- "New session" reopens the setup with the last brief.

## Triage (one at a time)

**When:** items arrive already made but not yet judged: ideas without
scores, a backlog with no priorities, claims marked "assumed".

**Why:** an unjudged item is stalled, not parked. A list with no priorities is
not a plan.

**Shape:**
- The tool says what's outstanding ("6 items still need a priority").
- It offers to walk through them: the item, the call to make, a progress bar with a visible end, and Skip and Discard.
- Making the call advances automatically.

## None (rare, and written down)

A settings page or a read-only report may need nothing. Write
"none, because…" in the map, so the gap is a decision rather than an oversight.
