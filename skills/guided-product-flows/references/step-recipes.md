# Step recipes

Step lists that worked, by kind of tool. Use them as a starting proposal for
Phase 1, then adapt them to the product's own names. "Gathers from" is where
the options come from. The guide offers them; it never fills them in silently.

## Planning and prioritising

| Tool kind | Steps | Gathers from |
|---|---|---|
| **Product backlog / roadmap** | 1. Release goal (what is the next release *for*?) → 2. What goes in (tested items first, ticked) → 3. Sort Must · Should · Could · Won't (warn above about 60% Musts) → 4. A job story for each Must ("When…, I want…, so I can…", with a draft built from the need it serves) | outcomes on the opportunity tree; experiments the user decided to continue; solutions on the tree; scored ideas, quick wins first |
| **Opportunity solution tree** | 1. Outcome (one measurable change) → 2. Opportunities (customer needs, from research) → 3. Focus (pick one) → 4. Solutions (aim for 3 or more) → 5. Test (the cheapest experiment for the riskiest one) | persona pains and jobs not yet on the tree |
| **Risk / assumption register** | One step per risk category (desirability, feasibility, viability: "What must be true for…?") → rank (impact × uncertainty) → choose what to test first | the value proposition's claims; business model blocks; anything marked "assumed" |
| **Experiment design** | 1. Which solution or assumption → 2. Method (cheapest first: interview, landing page, concierge, pilot) → 3. Sample and pass mark, *before* running → 4. Plan. Afterwards: log real counts → verdict from the numbers → the user decides continue · pivot · stop | the tree's solutions; the risk register's untested assumptions |

## Strategy and positioning

| Tool kind | Steps | Gathers from |
|---|---|---|
| **Go-to-market playbook** | 1. Who first (one segment you can win quickly) → 2. Positioning (fill-the-blanks Moore statement that builds itself) → 3. Channels (up to 4) → 4. Launch goals (countable in 90 days). Then an AI draft that keeps all four verbatim, or "Save without the draft" | personas; business model segments and channels; the biggest real competitor as "Unlike…" |
| **Competitor analysis** | 1. Who else (including "doing nothing", the status quo) → 2. Their strengths and weaknesses → 3. Where you win → 4. What they'll say, and your answer | value proposition; ecosystem actors; research notes |
| **Value proposition** | Customer side first (jobs → pains → gains), then the value map (products → pain relievers → gain creators) | personas' jobs, pains and gains, with their confidence |
| **Business model** | Decisions in dependency order: segments → value → channels and relationships → revenue → resources, activities, partners → costs. Each decision cascades only to the blocks it actually touches | value proposition; ecosystem |

## Setup and models

| Tool kind | Steps | Gathers from |
|---|---|---|
| **Financial model** | 1. Model and pricing → 2. Acquisition ramp → 3. Team and operating costs → 4. Unit economics. Then generate | business model revenue streams and costs |
| **Service blueprint** | 1. Stages of the journey → 2. Lane by lane (evidence, customer actions, frontstage, backstage, support) → 3. Systems and dependencies | business model channels and activities; personas |
| **Ecosystem map** | 1. Who's involved, by role (user, buyer, influencer, partner, regulator) → 2. Influence × interest → 3. Relationships | business model partners and segments; competitors |
| **Project / venture setup** | 1. Context → 2. Type → 3. What's new about it (with a clarity check: too vague, too technical, too narrow) → 4. Where it plays → 5. North-star outcome | none (this is the root that feeds everything) |

## Sessions and outputs

| Tool kind | Path | Gathers from |
|---|---|---|
| **Pitch rehearsal / practice chat** | Setup brief: 1. Who you're pitching, and the stage → 2. The ask → 3. The question you dread (suggested from gaps: untested high-risk assumption, no financial model, no real competitors, no customer evidence) | the deck's Ask slide; the risk register; experiments |
| **Pitch deck** | 1. Audience → 2. The ask and use of funds → 3. Key differentiator and market size → 4. Generate (split long generations to stay under timeouts) | value proposition; business model; financials; competitors |
| **1-pager / data room / summary** | Checklist: premise · customer and job · value · evidence from real customers · competitors · financial model · the ask · riskiest assumptions known | every tool it summarises |

## Other kinds of product

The recipes above come from a product-strategy app. The same paths fit other
products whose screens build on each other:

| Product | Tool | Path | Gathers from |
|---|---|---|---|
| **Analytics / dashboards** | A new dashboard | Guide: 1. Who reads it, and what decision it serves → 2. The 3–5 measures that inform that decision → 3. Compared with what (target, last period, segment) → 4. Who is alerted when, and at what threshold | the metrics already defined; existing dashboards' measures |
| | A weekly report | Checklist: each measure has data this period · each has a comparison · anomalies explained · owner named | the dashboards it summarises |
| **CRM / sales pipeline** | A new deal | Guide: 1. Which account (existing first) → 2. The problem they have, in their words → 3. Next step and date → 4. Stage, from the next step, not a guess | accounts; past notes and calls |
| | The pipeline | Triage: deals with no next step, or a next step in the past, one at a time | deals |
| **Learning / courses** | A learner's plan | Guide: 1. Goal → 2. What they know (from the assessment) → 3. Time per week → 4. Plan, built from the gaps | the assessment; the course catalogue |
| **Admin / settings** | Settings | Usually `none, because` it's a list of independent switches. A first-run setup across several settings is a guide, though. |
| **Projects / operations** | A project plan | Guide: 1. Outcome → 2. Milestones → 3. Risks (from past projects' issues) → 4. Owners | templates; past projects |
| | A status report | Checklist, assembled from the plan and the tasks | the plan; tasks; risks |

When a product's tools don't match any row, use `choosing.md` from first
principles: find the decisions, and say where each one's options come from.
